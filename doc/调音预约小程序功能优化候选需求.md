# 调音预约小程序功能优化候选需求

更新时间：2026-07-24

本文档用于记录后续可加入「车音工坊」小程序的功能优化候选项，方便先做产品确认，再进入设计和开发。内容参考了 GitHub 上常见的微信预约、车辆服务预约、线下门店服务类项目能力，并结合当前项目已有页面与云函数整理。

参考项目：

- StudyAppt 学员课时预约小程序：学员端、老师端、管理端、预约通知、名单管理、记录导出。
- vehicle-service-booking：车辆服务预约流程，包含服务浏览、预约日期时间、我的预约。
- CoreShop：服务商品、核销码、自定义表单、活动预约、门店核销等线下服务能力。
- bee 餐饮点餐外卖小程序：在线订座、门店参数、服务范围、订单/小票等门店运营能力。

---

## 1. 优先级建议

### P0 - 过审和主流程可用性

目标：确保微信审核人员第一次打开小程序时，可以真实进入预约流程，看到可预约内容，并完成一次预约提交。

建议先确认：

- 未登录用户能否浏览预约页。
- 未登录用户能否选择服务、日期、时段。
- 是否必须在提交前强制授权微信头像昵称。
- 审核环境是否有可用服务和未来可预约时段。
- 预约成功后，用户能否看到清晰结果。

### P1 - 预约闭环体验

目标：让客户和管理员都能清楚知道预约当前处于什么状态，以及下一步该做什么。

建议包含：

- 预约成功页或成功结果区。
- 用户端预约状态展示。
- 管理员确认、取消、完成预约。
- 用户取消预约。
- 预约详情页。

### P2 - 调音业务特色

目标：让小程序不像通用预约表，而是服务汽车音响调音场景。

建议包含：

- 车辆/设备档案。
- 调音需求采集表单。
- 服务套餐和适用场景说明。
- 复查/返调预约。
- 技师备注和客户标签。

### P3 - 运营增强

目标：减少人工沟通，提升管理效率。

建议包含：

- 订阅消息通知。
- 管理员日历视图。
- 批量生成时段。
- 预约记录导出。
- 数据统计。
- 在线客服入口。

## 2. P0 过审和主流程可用性

### 2.1 预约页不应一进入就强制跳转登录

现状风险：

- 当前小程序有「我的」页登录体系，但预约云函数本身可以通过微信云环境 openid 识别用户。
- 如果审核人员首次点击底部「预约」tab 时被立即跳到「我的」页，微信官方可能判断「预约功能无法使用」。

需求说明：

- 用户进入预约页后，应直接看到三步预约流程。
- 未登录状态不影响选择服务、选择日期、选择时段、填写联系人信息。
- 如确实需要用户身份，应在提交时由云函数使用 openid 记录预约归属，不要求先完善头像昵称。
- 头像昵称完善可以放在「我的」页，作为查看个人资料和预约记录的增强能力，而不是预约提交前置条件。

验收标准：

- 新用户首次打开小程序，点击「预约」tab 后不会被自动跳走。
- 新用户可以完成服务选择、时间选择、信息填写。
- 点击「确认预约」后，如果云环境可用，能创建预约记录。
- 预约记录中包含 `_openid`、服务、日期、时段、姓名、手机号、车型。

建议优先级：P0

### 2.2 审核环境必须有默认服务和未来时段

现状风险：

- 如果服务列表为空，用户会看到「暂无服务」。
- 如果未来日期没有时段，用户会看到「该日期暂无可预约时段」。
- 对审核人员来说，这两种情况都可能被理解为预约不可用。

需求说明：

- 至少准备 2 到 3 个启用服务项目。
- 至少准备未来 7 天内的可预约时段。
- 推荐每天至少 2 个时段，例如 `10:00-12:00`、`14:00-16:00`。
- 每个时段保留可预约容量，避免全部约满。

验收标准：

- 首页能看到服务列表。
- 预约页能看到服务列表。
- 用户选择未来 1 到 7 天内任意一个日期时，至少部分日期有可预约时段。
- 管理员可以在时段管理中检查和补齐未来时段。

建议优先级：P0

### 2.3 空状态要给出明确下一步

现状风险：

- 「暂无服务」和「暂无可预约时段」只表达结果，没有告诉用户该怎么办。

需求说明：

- 服务为空时提示：`暂无可预约服务，请稍后再试或联系门店`。
- 当天无时段时提示：`该日期暂无可预约时段，请选择其他日期`。
- 连续多天无时段时，可增加「联系门店」或「返回首页」入口。
- 管理员端可提示「未来 7 天可预约时段不足」。

验收标准：

- 用户遇到空状态时知道下一步操作。
- 审核人员不会误以为页面卡死或功能缺失。

建议优先级：P0

## 3. P1 预约闭环体验

### 3.1 预约成功结果页

需求说明：

- 预约提交成功后，不只显示 Toast。
- 展示一个明确的成功结果区或结果页。
- 内容包括预约编号、服务名称、日期时段、联系人、手机号、状态。
- 提供两个操作：`查看我的预约`、`返回首页`。

用户价值：

- 用户能确认预约已经提交。
- 避免 Toast 消失后用户不知道结果。

页面影响：

- 可在预约页新增成功状态。
- 或新增 `pages/bookingResult/index`。

建议优先级：P1

### 3.2 预约详情页

需求说明：

- 用户从「我的预约」点击预约卡片进入详情。
- 管理员从「预约管理」点击卡片进入详情。
- 详情页展示完整预约信息和状态流转记录。

建议字段：

- 服务名称
- 服务价格
- 预计耗时
- 预约日期
- 预约时段
- 预约状态
- 客户姓名
- 手机号
- 车型
- 调音需求或备注
- 创建时间
- 更新时间

用户价值：

- 用户能复查信息。
- 管理员处理预约时不用在列表卡片里找全部信息。

建议优先级：P1

### 3.3 预约状态闭环

需求说明：

- 保留当前状态：`pending`、`confirmed`、`completed`、`cancelled`。
- 用户端展示状态含义：
  - 待确认：已提交，等待技师确认。
  - 已确认：技师已确认，请按时到店。
  - 已完成：服务已完成。
  - 已取消：预约已取消。
- 管理员端支持：
  - 待确认 -> 已确认
  - 待确认 -> 已取消
  - 已确认 -> 已完成
  - 已确认 -> 已取消

验收标准：

- 用户和管理员看到同一条预约时，状态一致。
- 管理员操作后，用户端刷新能看到新状态。
- 取消或完成后的预约不可重复操作。

建议优先级：P1

### 3.4 用户取消预约规则

需求说明：

- 用户可以取消待确认预约。
- 已确认预约是否允许用户自助取消，需要产品确认。

可选规则：

- 方案 A：只允许取消待确认预约。
- 方案 B：预约开始前 24 小时允许取消已确认预约。
- 方案 C：已确认预约只能联系门店取消。

推荐方案：

- 先采用方案 A，规则简单，开发量小，风险低。

建议优先级：P1

## 4. P2 调音业务特色

### 4.1 车辆档案

需求说明：

- 用户可以保存常用车辆信息。
- 预约时自动带出最近使用的车辆。

建议字段：

- 车辆品牌
- 车型
- 年款
- 车牌号后四位（可选）
- 音响系统/主机型号（可选）
- 改装件信息（可选）

用户价值：

- 老客户复预约更快。
- 技师提前了解车辆基础情况。

页面影响：

- 「我的」页新增「我的车辆」入口。
- 预约表单支持选择已有车辆或临时填写。

建议优先级：P2

### 4.2 调音需求采集表单

需求说明：

- 在预约表单中增加调音相关问题。
- 这些字段可以先作为可选项，避免增加预约门槛。

建议字段：

- 当前问题：低音浑、声场偏、齿音重、人声不清、其他。
- 期望风格：流行、人声、摇滚、电子、均衡、赛道/竞技。
- 是否首次调音：是/否。
- 是否有改装清单：原厂/已改装/不确定。
- 是否需要故障诊断：是/否。

用户价值：

- 客户不用在备注里自由发挥。
- 技师能提前判断服务复杂度。

建议优先级：P2

### 4.3 服务套餐和适用场景

需求说明：

- 服务项目不只展示名称、价格和时长，还要解释适合谁。

示例套餐：

- 基础听感调音：适合日常听歌、轻度调整。
- 进阶系统调校：适合已改装喇叭/功放/DSP 的车辆。
- 故障诊断：适合有噪音、偏音、无声、失真等问题。
- 复查微调：适合调音后一段时间回来微调。

建议字段：

- 适用场景
- 服务内容
- 不包含内容
- 注意事项
- 预计耗时
- 价格区间

用户价值：

- 降低咨询成本。
- 避免客户误选服务。

建议优先级：P2

### 4.4 复查/返调预约

需求说明：

- 已完成预约可以发起复查预约。
- 复查预约自动关联原预约。

用户价值：

- 调音业务常见“过几天再微调”的场景可以闭环。
- 技师能看到客户上次服务记录。

建议优先级：P2

## 5. P3 运营增强

### 5.1 订阅消息通知

需求说明：

- 用户提交预约后，引导订阅预约状态通知。
- 管理员确认、取消预约时，给用户发送订阅消息。
- 预约前一天或当天发送提醒。

注意事项：

- 微信订阅消息需要配置模板。
- 用户必须主动授权订阅。
- 不建议一开始就做复杂提醒规则，可以先做「管理员确认后通知」。

建议优先级：P3

### 5.2 管理员日历视图

需求说明：

- 管理员按日期查看预约。
- 日期上显示预约数量。
- 点击某天查看当天预约列表。

用户价值：

- 比纯列表更适合排班。
- 能快速发现某天过满或无预约。

建议优先级：P3

### 5.3 批量生成可预约时段

需求说明：

- 管理员选择日期范围、每天开放时段、每时段容量，一键生成。

示例：

- 日期范围：未来 14 天。
- 每天时段：10:00-12:00、14:00-16:00、16:30-18:30。
- 最大预约数：1。
- 排除日期：每周一或指定休息日。

用户价值：

- 避免管理员每天手动新增时段。
- 降低审核环境没有时段的风险。

建议优先级：P1 到 P2

### 5.4 预约记录导出

需求说明：

- 管理员可以导出预约记录。
- 可按日期范围和状态筛选。

导出字段：

- 创建时间
- 预约日期
- 预约时段
- 服务名称
- 客户姓名
- 手机号
- 车型
- 状态
- 备注

用户价值：

- 方便对账、复盘、客户回访。

建议优先级：P3

### 5.5 在线客服入口

需求说明：

- 首页、服务详情、预约空状态、预约成功页可放置客服入口。
- 用于复杂改装和调音需求咨询。

用户价值：

- 对不确定选哪个服务的客户更友好。
- 可以减少无效预约。

建议优先级：P3

## 6. 建议的确认清单

请先确认以下问题，再进入下一轮设计和开发：

1. 预约是否允许未完善微信头像昵称的用户提交？
2. 用户提交预约后，是立即算预约成功，还是必须管理员确认后才算成功？
3. 已确认预约是否允许用户自助取消？
4. 服务价格是固定价格、价格区间，还是到店确认？
5. 车辆档案是否需要保存车牌信息？
6. 调音需求采集表单哪些字段必须填写？
7. 是否需要做订阅消息通知？
8. 管理员是否需要批量生成未来时段？
9. 是否需要导出预约记录？
10. 是否需要在线客服入口？

## 7. 推荐实施顺序

### 第一阶段：过审稳定版

- 预约页不强制跳转登录。
- 准备默认服务和未来时段。
- 优化服务/时段空状态。
- 预约提交成功后展示明确结果。

### 第二阶段：预约闭环版

- 增加预约详情页。
- 完善用户端和管理员端状态流转。
- 明确用户取消预约规则。
- 增加批量生成时段。

### 第三阶段：调音专业版

- 增加车辆档案。
- 增加调音需求采集表单。
- 优化服务套餐展示。
- 支持复查/返调预约。

### 第四阶段：运营增强版

- 订阅消息通知。
- 管理员日历视图。
- 预约记录导出。
- 在线客服入口。
